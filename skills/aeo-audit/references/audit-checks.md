# Audit checks

Use only checks relevant to the target pages and buyer questions. [P01](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p01)

## Surface and access contract

- Name each product surface, consumer/API context, locale or geography, and search/grounding mode in scope. [C01](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c01)
- Inspect access per crawler purpose. Current official controls include Googlebot for Google Search; `OAI-SearchBot` for ChatGPT Search versus `GPTBot` for training; `Claude-SearchBot` and `Claude-User` versus `ClaudeBot` for training; and `PerplexityBot` plus `Perplexity-User`. Verify the current names, behaviors, and published IP ranges in official documentation before reporting. [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02)
- Do not assume a global `*` disallow describes every purpose. Advertising verification is its own class: one platform documents its ads crawler as ignoring the global `*` robots group with the ad publisher's permission, and another documents an ads crawler whose collected data is not used for foundation-model training. Report ad-verification access separately when the site runs ads. [C62](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c62)
- Check each vendor's user-triggered fetcher against its own current documentation rather than generalizing. The same nominal purpose carries opposite robots.txt semantics across platforms, with some user-fetch agents documented as generally ignoring robots.txt and at least one documented as respecting it. [C63](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c63)
- Treat `robots.txt` as a crawler preference, not access control. Sensitive content requires authentication or removal. Remember that a crawler blocked from a page may be unable to read its `noindex` directive. [C03](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c03)
- Test CDN, WAF, authentication, bot verification, and rate-limit behavior when evidence is available. A permissive `robots.txt` does not prove successful retrieval. [C03](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c03) [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04)
- Record the `robots.txt` response itself, not only its rules: status code, redirect chain, byte size against the documented parse limit, cache headers, and retrieval time. A `5xx`, `429`, or timeout can suspend crawling before a cached copy is reused, most `4xx` responses are treated as no file at all, and directives past the size limit never take effect. [C46](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c46)
- Resolve directives the way the target crawler resolves them: one most-specific user-agent group applies, the longest matching path rule wins inside it, genuine conflicts resolve to the least restrictive outcome, and unsupported fields are ignored. Flag a crawler-specific group that omits rules the wildcard group carries, because those wildcard rules no longer apply to that crawler. [C47](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c47)
- Test access at the delivery layer as well as the origin. Content-delivery and bot-management platforms can allow or block the search, agent, and training crawler classes independently of the site's `robots.txt`, and their defaults change on announced dates, so report the response actually delivered to each crawler class in scope and confirm whether an observed block is the owner's intent. [C43](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c43)
- Record any machine-readable licensing declaration separately again, including a `License:` directive in `robots.txt` or an equivalent HTTP `Link`, HTML, feed, or embedded-media pointer, and summarize the usage categories, payment model, and attribution terms it asserts. These are industry recommendations without automatic enforcement, so report what the site asserts and where, never that an operator complied. [C60](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c60)
- Record post-access usage declarations such as `Content-Signal` lines in `robots.txt` or a `Content-Usage` header separately from crawl access. They apply only to resources that are already crawlable, depend on each operator's voluntary compliance, and rest on unratified drafts, so report them as declared owner intent rather than as a retrieval state or a visibility lever. [C44](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c44)
- Do not authenticate a crawler from its `User-Agent` string. For server-log or allowlist conclusions, use the operator's current published IP ranges or documented forward-confirmed reverse DNS where available; label a request made with a spoofable user-agent string as a simulation. [C28](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c28)

- Where an operator supports signed requests, prefer that evidence over an address match: a valid HTTP message signature whose key resolves through the operator's published directory identifies the client per request, while IP ranges and reverse DNS identify a network. Record which method produced the conclusion, note that the specification is an individual Internet-Draft rather than a ratified standard, and treat an unsigned request as unverified rather than illegitimate. [C58](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c58)

## Retrieval and indexing

- HTTP status, redirect target, content type, and canonical consistency. [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02) [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04)
- Interpret status codes by their documented crawler effect: content from `4xx` URLs is not used and previously indexed URLs are removed, `404` and `410` are handled identically, `429` counts as server overload rather than a client error, and sustained `5xx` reduces crawl rate before indexed content is dropped. Never present `401` or `403` as a crawl-rate control. [C61](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c61)
- Compare the status with the raw and rendered body. Flag error, empty, or missing-primary-content pages returned as `200`; recognize valid conditional `304` responses; and distinguish a timestamped transient `429` or `503` from persistent unavailability using repeat observations or logs when available. [C37](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c37)
- `robots.txt`, page-level robots directives, `X-Robots-Tag`, and applicable snippet/preview controls. [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02) [C03](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c03)
- For Google Search AI features, verify `noindex`, `nosnippet`, `max-snippet`, and `data-nosnippet` in the response Googlebot can retrieve. Record their actual scope and confirm publishing intent before recommending a change. [C23](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c23)
- Resolve preview and generative-reuse directives per engine. Bing treats `nocache` as allowing only URL, title, and snippet in its generative answers and `noarchive` as excluding the page from those answers and from Microsoft generative training, both while ordinary search results continue, and `nocache` prevails when a page carries both. Do not report one combined preview status across engines. [C49](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c49)
- Meaningful raw HTML, rendered content, and accessibility-tree parity for important facts and actions. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C08](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c08)
- When important facts or links require JavaScript, test the initial response and rendered DOM separately, including blocked scripts, failed requests, console errors, meaningful status codes, and at least one relevant non-rendering fetch path. Recommend server-side or prerendered output only when the observed target surface needs it. [C24](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c24)
- Stable public URLs for evidence-bearing sections. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04) [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- Confirm that every important evidence page is reachable through at least one contextual, crawlable `<a href>` link whose destination resolves without requiring a script-only click handler or fragment-routed content. Treat sitemap presence as complementary, not a replacement for navigable internal discovery. [C32](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c32)
- Internal discovery, duplicate variants, sitemap coverage, and truthful `lastmod` values. [C07](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c07) [C17](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c17)
- Check sitemap mechanics against the protocol and the engine's stated use: fully qualified URLs, the 50,000-URL and 50 MB per-file limits, W3C Datetime `lastmod`, and index files. Report `changefreq` and `priority` as values Google ignores rather than as tuning levers. [C48](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c48) [S58](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s58)
- Verify that `lastmod` tracks real changes to main content, structured data, or links. A build-time or copyright-date stamp applied site-wide is an inaccurate signal an engine can learn to discount, not a freshness gain, and sitemap submission guarantees neither download nor crawling. [C48](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c48) [C17](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c17)
- For duplicate or near-duplicate URLs, compare redirects, self-referencing and alternate canonicals, sitemap entries, internal links, and `hreflang`; report conflicting signals instead of prescribing canonicalization from one tag alone. [C21](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c21)
- For localized pages, verify fully qualified reciprocal `hreflang` sets, self-links, valid language-region codes, an intentional `x-default` when useful, and canonicals that preserve the intended same-language or regional page. Check the actual visible language; do not infer it from `lang` or `hreflang` alone. [C25](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c25)
- Index or URL inspection evidence when authorized; eligibility is not proof of indexing or serving. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04)
- Keep URL Inspection's indexed result, crawl timestamp, and Google-selected canonical separate from its live test. A successful live test shows current fetch/indexability signals but does not establish canonical selection, indexing, quality eligibility, or serving. [C29](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c29)
- Diagnose crawl-budget constraints only for sites large, fast-changing, or demonstrably stuck in discovery at a relevant scale. For ordinary sites, prefer sitemap freshness, indexing reports, internal discovery, and concrete crawl errors over speculative crawl-budget work. [C33](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c33)
- Compare responses across relevant signed-in/out, cookie, locale, geography, device, and verified-crawler contexts. Legitimate personalization may differ, but content served specifically to a crawler to manipulate retrieval or ranking is not an acceptable fix. [C34](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c34)

## Entity clarity

- Unambiguous brand name, category, audience, and primary use case. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05)
- Consistent aliases, canonical domain, contact, and ownership facts. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- Visible facts aligned with Organization, Product, SoftwareApplication, Article, or other applicable schema. [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- Check that organization identity markup sits on the home page or one page describing the organization, carries only disambiguation identifiers the owner can substantiate, and uses `sameAs` links to independently maintained profiles that agree with the visible page. [C45](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c45) [S55](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s55)
- Treat a knowledge panel as an automatically generated outcome drawn from many sources, not a deliverable. If panel facts are wrong, record the correction path open to a verified representative instead of promising a panel or a specific panel change. [C45](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c45) [S56](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s56)
- No schema-only claims. [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- Name the tool behind every structured-data verdict. The Rich Results Test reports which Google rich results the markup can generate, the Schema Markup Validator checks schema.org conformance without Google feature warnings, and Search Console rich result reports describe what Google already processed. None of them reports indexing, display, or citation. [C52](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c52) [S63](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s63)
- When review markup is relevant to Google, confirm that the reviews and ratings are visible, item-specific, sourced as represented, and not aggregated from other sites. Report self-controlled `LocalBusiness` or `Organization` reviews as ineligible for Google's star review feature, not as invalid reviews or a general AEO defect. [C42](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c42)
- Applicable owner-controlled feeds and profiles aligned with the page, such as Merchant Center, Business Profile, or Bing Places. [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- For agent-initiated payment flows, record how user authorization is captured and evidenced, including signed mandates, their constraints, and the resulting audit trail, and verify the arrangement with the merchant. These protocols are vendor-led and still standardizing, and they govern accountability for a purchase rather than retrieval or visibility. [C59](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c59)
- For agentic checkout, treat a platform commerce integration as a distribution path separate from public-web retrieval. Record the feed format and refresh cadence, report recommended attributes as improving ranking and relevance without guaranteeing display or purchasability, and confirm who remains merchant of record and responsible for validation, tax, payment, and fulfillment. [C57](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c57)
- For commerce questions, compare current visible price, currency, availability, variants, shipping, and returns with applicable structured data and surface-specific feeds. Name the destination surface and integration path; do not assume one feed supplies Google, ChatGPT, Bing, or another product. [C27](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c27)
- Text, images, video, and metadata referring to the same entity without material conflicts. [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)

## Answer extraction

- Clear headings and concise passages that directly answer target questions. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)
- Capability, limitation, pricing, compatibility, methodology, and comparison facts in extractable text. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05)
- Tables understandable without layout or image-only labels. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C08](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c08)
- For evidence-bearing images or video, verify a crawlable landing page, relevant surrounding text, accurate captions or alt text where appropriate, accessible media URLs and thumbnails, and metadata that agrees with what users can see. Do not use alt text as a hidden keyword or claim channel. [C31](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c31)
- Visible labels and native HTML semantics; accurate accessible names, roles, and states for relevant interactions. [C08](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c08)
- For a buyer question that depends on an interactive task, test the complete scoped path rather than one screen: controls, visible and accessible labels, state changes, status and error messages, keyboard operation, and authentication boundaries. Report task-specific failures without claiming general WCAG conformance from this check. [C38](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c38)
- If the site registers WebMCP tools, review them as application surface rather than visibility work: each tool's name, description, and input schema should match what it actually does, results carrying user-generated or external content should be marked untrusted, state-changing tools should be distinguishable from read-only ones so an agent can seek confirmation, and tools should be exposed only to trusted origins. Record that the specification is a Community Group draft and not a W3C Standard. [C56](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c56)
- When browser-agent readiness is in scope, read Lighthouse's Agentic Browsing audits as a deterministic build-quality signal only. Google publishes the category without a 0-100 score and calls it experimental and based on proposed standards, so record the individual audit results and do not convert them into a visibility, ranking, or citation finding. [C51](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c51)
- Explicit publication or substantial-update dates where freshness matters, consistent with structured data. [C07](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c07)
- Check any proposed rich-result feature against Google's current supported-feature gallery at execution time. FAQ rich results are now limited to well-known, authoritative government and health websites and How-to was deprecated with its documentation removed, so neither is an available result type for a typical site. [C55](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c55) [S66](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s66)
- No assumption that tiny content chunks, a fixed word count, or FAQ formatting is required. [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)

## Evidence quality

- Original information, first-hand experience, research, or analysis beyond a rewrite of existing summaries. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05)
- Important claims linked to the closest primary documentation or credible independent evidence. [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- Comparisons state criteria and tradeoffs rather than unsupported superiority. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- Measurements include method, population, date, and limitations. [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- For U.S.-directed commercial content, identify material express and implied objective claims and whether the represented level of support existed before publication. Preserve jurisdiction and qualifications; escalate uncertain, regulated, health, safety, or financial claims for qualified review instead of issuing a legal conclusion. [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19) [C40](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c40)
- For reviews or testimonials, record whether the business merely hosts or actively disseminates them, the reviewer's claimed experience, incentives, material relationships, selection or suppression policy, and whether a company-controlled source is presented as independent. Apply jurisdiction-specific rules only to the relevant audience and flag missing provenance without assuming every hosted review must be individually authenticated. [C41](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c41)
- Report experience, expertise, authoritativeness, and trust as observable page evidence such as named authorship or review, stated method, first-hand detail, disclosed ownership and relationships, and correction history. Do not assign an E-E-A-T score or promise a rating change; Google calls it an evaluation concept, says trust matters most, and says rater data is not used directly in ranking. [C53](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c53)
- Authorship or review ownership, relevant expertise, creation method, and update history where readers would expect them. [C05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c05) [C07](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c07)
- Citations support the exact adjacent claim; conflicting or stale sources are disclosed. [C13](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c13) [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- Statistics and quotations are relevant, contextualized, and genuine—not inserted to meet an AEO quota. [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09) [C20](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c20)
- For subscription, registration, or paywalled pages intended for indexing, verify that visible access boundaries and applicable `isAccessibleForFree` or `hasPart` markup agree. Do not recommend sending protected content to the browser merely to make it extractable. [C26](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c26)

## Source ecosystem

- Identify which independent domains appear in observed answers. [C18](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c18)
- Distinguish sources the brand controls from independent sources it cannot directly edit. [C18](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c18)
- Recommend outreach or third-party edits only as a proposed external action requiring user authorization. [P02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p02)
- Flag fabricated, paid, undisclosed, or inauthentic mentions as prohibited rather than an opportunity. [C20](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c20)
- Flag scaled pages, scraped or lightly transformed summaries, and third-party sections published mainly to exploit the host's reputation when their primary purpose is search manipulation rather than user value. Do not mistake disclosure or automation method for evidence that the content is acceptable. [C30](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c30)

## Native measurement

- Check the Google Search Console generative AI report when available; record rollout, canonical aggregation, row, privacy, and preliminary-data limits. [S07](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s07) [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10)
- Check Bing Webmaster Tools AI Performance when available. Preserve filters and comparison basis for citations, cited pages, grounding queries, intents, topics, citation share, or comparison views; grouped queries are not exact prompts, and these dimensions do not indicate rank, authority, or causality. [S12](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s12) [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10) [C36](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c36)
- Keep Search Console chart totals and table rows as separate quantities. Rare queries are anonymized out of the table yet still counted in chart totals unless a query filter is applied, the table is row-capped, and filtered `match` and `does not match` subtotals need not add up to the unfiltered total, so summed rows are not a total and a missing row is not a zero. [C54](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c54) [S65](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s65)
- Segment verified referrals such as `utm_source=chatgpt.com`, search-console impressions, server-log fetches, public answers, and third-party estimates. They are different measurements. [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11) [C16](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c16)

## Unsupported shortcuts

- Google explicitly says `llms.txt`, special AI markup, artificial chunking, AI-only rewrites, inauthentic mentions, and overfocused structured data are not requirements for its generative Search features. [S01](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s01) [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)
- Describe `llms.txt` accurately rather than dismissing it: a community Markdown convention with a defined structure and an agent audience, no documented search-visibility effect, and no source linking it to answer-engine citation. Recommend one only when a named consuming system is in scope, and state the benefit in that system's terms. [C50](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c50)
- Structured data can clarify applicable entities or unlock supported search features, but valid markup does not guarantee display or citation and must match visible content. [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- IndexNow and sitemaps support discovery or freshness; neither proves crawl, indexing, ranking, or citation. [C17](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c17)
- Treat feature eligibility as perishable. Google withdraws supported result types as well as adding them, so a markup recommendation carried over from older guidance can target a feature that no longer exists. [C55](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c55)
- Passing every deterministic check proves readiness only. It does not prove visibility. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04)
