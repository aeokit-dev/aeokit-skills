# Evidence levels

Never blend these levels into a single score or use evidence from a lower level to claim an outcome at a higher one. [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11)

## Deterministic verification

Establishes properties that can be tested directly: successful retrieval under a named user agent, crawler directives, HTTP and rendered behavior, extractable text, accessibility semantics, internal links, visible claim/schema/feed/profile parity, valid structured data, source links, build success, and content consistency. [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02) [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04) [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06) [C08](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c08)

It does not establish indexing, model ingestion, recommendation, ranking, mention, or citation. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04)

Record the exact page or file, observation time, tool or access mode, and before/after value. For volatile crawler controls, verify current official platform documentation rather than relying on a memorized bot list. [P03](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p03) [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02) [C12](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c12)

A request that merely sends a crawler `User-Agent` is a fetch simulation, not verified crawler traffic. When origin matters, use current operator IP ranges or documented DNS verification and preserve the source IP and verification method. [C28](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c28)

Where the operator supports signed requests, a verified HTTP message signature is per-request evidence of client identity and is stronger than an address match. Record the verification method, the key directory consulted, and the signature's validity window, and keep the result labelled as draft-based verification. [C58](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c58)

## Owner telemetry

Uses first-party data available to the site owner, such as Google Search Console's generative AI report, Bing Webmaster Tools AI Performance, verified referrals, URL inspection, and server logs. [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10)

Search telemetry is also deliberately incomplete. Never sum exported table rows into a coverage or visibility total: anonymized rare queries never appear as rows yet count toward chart totals, tables are row-capped, and filtered subtotals need not reconcile to the unfiltered total. Record which filters produced every figure you quote. [C54](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c54)

Owner telemetry is stronger evidence of the measured platform event than a third-party estimate, but it inherits product-specific sampling, aggregation, privacy, rollout, and attribution limits. An impression, crawler request, citation count, or referral is not automatically a recommendation or conversion. [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10) [C16](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c16)

## Directional grounded simulation

A fresh observer receives the unchanged buyer question and the eligible post-change content or evidence snapshot, but not the operator's hypothesis or intended verdict. It tests whether an independent researcher can understand and use the evidence. [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11) [C15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c15)

It does not establish performance on ChatGPT, Claude.ai, Perplexity, Google, or another public consumer surface. [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11)

## Production observation

A named public consumer surface returns an answer for the unchanged prompt after deployment. Store the raw answer, timestamp, provider, product surface, displayed model when available, web-search or grounding mode, account state, locale, geography, device, prompt hash, corpus version, sample number, extracted entities, citation context, destination URLs, and parser version. [C12](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c12)

This is a point-in-time observation. It does not by itself establish causality, ingestion timing, or a durable ranking. [C15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c15)

An API, test agent, or subscription-backed coding agent is not a production observation unless it genuinely operates the named consumer surface under recorded conditions. [C01](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c01) [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11)

## Business outcome

Uses a predeclared downstream measure such as verified visits, qualified leads, conversions, revenue, or task completion. Preserve the attribution window and known channel overlap. Visibility evidence alone cannot establish business impact. [C16](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c16)

## Language

Use `verified` only with the property verified: “schema matches the visible product name.” Use `reported by owner telemetry` for native platform data and state its aggregation. Use `observed` for public answers: “the brand appeared in 3 of 5 observations.” Reserve `improved` for a compatible before/after metric with uncertainty and an explicit causality caveat. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04) [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10) [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11) [C15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c15)

## Research-backed patch rules

- Google's current guidance says generative Search builds on foundational Search, unique people-first content, crawlability, and clear technical structure. It explicitly rejects mandatory `llms.txt`, artificial chunking, AI-only rewrites, inauthentic mentions, and special generative schema. [S01](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s01) [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)
- Structured data must represent visible content and enables eligibility rather than guaranteed display. [S04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s04) [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- Visible and structured dates should reflect publication or substantial updates, not cosmetic freshness. [S05](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s05) [C07](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c07)
- The KDD 2024 GEO paper supports testing relevant citations, credible quotations, and statistics, but its GPT-3.5 benchmark and 200-item Perplexity file-upload experiment do not establish a live ranking uplift. Use these devices only when true, supported, and useful. [S16](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s16) [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)
- For browser-agent tasks, prefer native semantics and accurate visible labels before adding ARIA. [S15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#s15) [C08](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c08)
- If essential evidence exists only after client rendering, first fix failed or blocked resources and status behavior; use server-side or prerendered output when a target crawler cannot reliably execute the required JavaScript. Do not prescribe dynamic rendering as a universal AEO layer. [C24](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c24)
- Before rewriting any directive, confirm that `robots.txt` is served successfully, is inside the documented parse limit, and is not being served from a stale cache after an outage. Rule text cannot fix a file the crawler could not read or truncated. [C46](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c46)
- When a patch changes `robots.txt`, check its effect on every purpose class in scope, including advertising verification, whose crawler may ignore the global `*` group entirely. [C62](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c62)
- When adding a crawler-specific `user-agent` group, restate every rule that crawler still needs. Only the most specific matching group applies, so a narrow group silently cancels the wildcard group's rules for that crawler. [C47](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c47)
- Choose a removal or error status for what it actually does to retrieval and indexing rather than to shape crawl rate: `404` and `410` behave identically, and `401` or `403` will not slow a crawler. [C61](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c61)
- Set `lastmod` only from a real change to main content, structured data, or links, and leave `changefreq` and `priority` out of the argument for a patch since Google ignores them. [C48](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c48)
- Choose preview and reuse directives per engine and per owner intent. Bing's `nocache` and `noarchive` decide generative-answer inclusion, linking, and Microsoft generative training independently of ordinary search results, so do not copy a Google directive set onto other surfaces or strip an intentional restriction to raise extractability. [C49](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c49) [C23](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c23)
- When a target surface cannot retrieve a page, check the delivery and bot-management layer before editing origin directives. An edge rule or a changed platform default can block a crawler class while the origin configuration still reads as permissive, and the fix then belongs to the platform configuration and the owner's intent rather than to `robots.txt`. [C43](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c43)
- Treat a licensing declaration as the owner's commercial decision, not a patch you propose for visibility, and never author or alter one without explicit instruction and, where money or rights are involved, qualified review. [C60](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c60) [P02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p02)
- Adjust `Content-Signal` or `Content-Usage` declarations only to record what the owner actually wants, and state plainly that adding, removing, or loosening them applies solely to already-crawlable resources and has no established effect on retrieval, selection, or citation. [C44](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c44)
- For entity gaps, place organization identity markup on the home page or one organization-describing page, add only identifiers the owner can substantiate, and point `sameAs` at profiles the brand genuinely maintains and keeps consistent with the visible page. [C45](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c45)
- Improve evidence a reader could verify—named authorship or review, stated method, first-hand detail, disclosed relationships, visible corrections—rather than targeting an E-E-A-T score that Google neither publishes nor uses as a ranking factor. [C53](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c53) [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
- Confirm a rich-result feature still exists before proposing markup for it, checking the current supported-feature gallery rather than an older recommendation. Leaving already-published markup in place is a separate decision from whether the feature is still available. [C55](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c55) [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
- Add or maintain `llms.txt` only when a named system in scope consumes it, and say which system and what it gains. Do not present the file as a Search, answer-engine, or citation improvement. [C50](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c50) [C09](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c09)
- Do not propose WebMCP tools as a visibility improvement. Treat them as agent-interaction engineering on a Community Group draft that is not a W3C Standard, and pair every tool with an honest description and schema, untrusted marking for external or user-generated results, a read-only or state-changing distinction, and origin restrictions. [C56](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c56) [P02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p02)
- For browser-agent readiness, fix the underlying accessibility tree, labels, and layout stability rather than an audit result, and report Lighthouse Agentic Browsing outcomes as experimental, unscored signals whose proposals may still change. [C51](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c51)
- State which validator produced a structured-data pass and what that tool covers, because Google feature eligibility and schema.org conformance are different results and neither establishes display. [C52](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c52)
- Make important pages discoverable with real anchors and resolvable URLs. Do not rely only on sitemaps, click handlers, router attributes without `href`, or URL fragments that swap primary content. [C32](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c32)
- Optimize crawl budget only when site scale, update frequency, crawl reports, or server evidence demonstrates a constraint; increased crawl rate is not itself a ranking or citation outcome. [C33](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c33)
- For multilingual or regional patches, keep each page's visible language, reciprocal `hreflang` cluster, canonical, and fallback behavior coherent; do not collapse legitimately localized pages into one global canonical. [C25](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c25)
- Preserve real access boundaries on gated content. Add paywall markup only for content the publisher intends search engines to crawl and index, and never expose protected text client-side solely for extraction. [C26](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c26)
- For agentic commerce work, keep the platform feed and the public product page as separate deliverables with independent freshness, and never promise inclusion or purchasability from feed coverage alone. [C57](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c57)
- For commerce patches, update the visible product source of truth and each applicable feed or profile together. Treat product markup, Google Merchant Center, OpenAI or partner catalog integrations, and other surfaces as distinct distribution paths with independent eligibility and freshness. [C27](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c27)
- Keep media evidence useful without the media renderer: add accurate nearby text, captions or alt text when appropriate, stable media URLs, and matching metadata. Do not stuff alt text or duplicate a transcript where it does not help users. [C31](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c31)

## Verification order

1. Confirm the build and visible page behavior. [C04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c04) [P04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p04)
2. Verify retrieval, directives, canonicals, preview controls, and structured-data parity. [C02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c02) [C03](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c03) [C06](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c06)
3. When Search Console is available, compare indexed and live URL Inspection evidence rather than treating a passing live test as proof that the changed page is indexed or selected as canonical. [C29](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c29)
4. Confirm every added claim against its source and disclose method, date, population, and limits for quantitative claims. [C19](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c19)
5. Run a blind grounded simulation only when it answers a real uncertainty. [C11](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c11) [P04](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p04)
6. After separately authorized deployment and adequate recrawl time, compare compatible owner telemetry and public observations. [P02](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#p02) [C10](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c10) [C12](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c12) [C15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c15)
7. Keep the result inconclusive when the sample, observation window, or access conditions do not support a directional claim. [C14](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c14) [C15](https://github.com/aeokit-dev/aeo-skills/blob/v0.1.0/research/report-source.md#c15)
